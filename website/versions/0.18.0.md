# Mettle 0.18.0

This one's big. 663 commits, and most of them went into one idea: you should be able to program the compiler from inside the program you're compiling.

So in 0.18.0 build rules, struct layouts, optimizer passes and the register allocator are plain Mettle functions you write in your own code. The compiler checks every pass you write against the code it replaced, and stops the build if the program's behaviour changes.

The part I've wanted to ship for the longest is live programs. You save a file, and the running program switches to the new code with every frame on the stack carried over, locals and all. If it crashes, it pauses until you save a fix and then keeps going.

The code got a lot faster too. Suite 3 now runs at 1.04 times clang -O3, down from 1.18, and three of its sixteen programs beat clang.

Beyond that, Mettle now runs on macOS and Apple GPUs, `if` and `switch` give values, local bindings can leave their types off, the standard library goes all the way from system calls up to HTTP/2, and `mettle pkg` installs from a registry that already holds 40 packages.

## Breaking changes

Nothing was removed. Every keyword, flag and standard library function is still there with the same signature. A few behaviours changed though, and you'll want to know about them before you upgrade:

- **`@pure` is checked now.** If a `@pure` function writes anything, you get F0004. The compiler works out purity on its own these days, so the decorator no longer changes the generated code.
- **Bitwise operators and shifts on a `bool` give you an `int32`.** `flag | 2` used to be typed `bool` and print `true`. Now it prints `3`.
- **Constant expressions wrap at their own type**, the same way they do at run time. `(int8)100 + (int8)100` used to fold to `200`; now it's `-56`, and `2147483647 + 1` is `-2147483648`.
- **Integer literals can't start with 0.** `0755` used to quietly mean 755. Write `0o755` if you meant octal, or `755` if you didn't.
- **`main` returns an exit status.** `fn main() -> string` used to build and then crash. Now it's a compile error.
- **A function with a result type has to return on every path.** One that could fall off its closing brace used to compile and hand back whatever was in the register. Now that's E0003.
- **Unused private functions in imported modules get type checked.** A module with a broken function nobody called used to compile anyway. It doesn't anymore.
- **Unknown escapes in string literals are errors.** `"a\xC3b"` used to be six characters with no warning at all.
- **String literals keep their full length.** `"a\0b".length` is 3 now. It used to be 1.
- **`"{x}"` keeps the sign of negative zero**, so `-0.0` prints as `-0.0`.
- **The minimum `int64` divided by -1 gives you the minimum back**, like the narrower widths always did. It used to kill the process. Dividing by zero still traps.
- **Index arithmetic runs at `int64`.** The math inside brackets, and an integer added to a pointer, no longer wraps to `int32` on the way to becoming an address.
- **The automatic pool layout pass is gone.** If you relied on it, declare the layout you want with `@soa` or `@hot_cold`.
- **If the register allocator can't handle a function, that's a compile error.** I deleted the spill-everything fallback, all 9,700 lines of it.
- **Ordinary builds take longer.** More on that under [Compile speed](#compile-speed).

## Programming the compiler

**[Rules](https://github.com/The-Mettle-Project/Mettle/blob/v0.18.0/docs/rules.md).** A rule is a function that runs while your program compiles, and it can stop the build. Here's one that bans recursion in a module:

```mettle
import "std/rule";

@rule fn no_recursion(p: Program) -> Verdict {
  for f in p.functions {
    if (f.module == "" && f.is_recursive) {
      return verdict_fail(f.site, "this module forbids recursion");
    }
  }
  return verdict_pass();
}
```

Rules can look at the program, the machine code it compiles to, its memory behaviour and recorded runs. A rule can also include a fix, which `--fix` applies for you. If a module exports its rules, they apply to every program that imports it, which lets a library enforce how it gets used.

**[Layouts](https://github.com/The-Mettle-Project/Mettle/blob/v0.18.0/docs/metaprogramming.md).** A `@layout` function decides where a struct's fields live. The layouts I ship, `@soa`, `@hot_cold`, `@compact`, `@tagged` and `@allocate_with`, are written exactly this way, as library code. Code that uses the struct doesn't change at all: `ps[i].x`, `&a[i]`, `new T` and pointer arithmetic keep working. When a type gets split across regions, a `T*` to it becomes a 24-byte reference carrying base, index and count, so debug and `--safe` builds can check every access.

**Generators.** A `@generate` function reads a function's IR, a type or a trait and writes Mettle source from it. That's how `@memoize`, `@trace`, `@dyn` and `grad` are built. `grad` differentiates through structs passed and returned by value, and generated source can import modules and use generics like any code you'd write by hand.

**Optimizer passes.** A `@pass` function takes one function's IR as a list of operations and returns the new list, at the point in the pipeline you name. Before the compiler keeps your result, it runs it against the original on generated inputs, and if the behaviour changed the build stops with L0007.

**Register allocation.** A `@regalloc` function gets each vreg's allowed registers and neighbours and returns an assignment. If the assignment is wrong, the build stops and points at your function. `std/regalloc` ships a `chaitin_briggs` allocator written in Mettle that you can start from.

**[Rewrite rules](https://github.com/The-Mettle-Project/Mettle/blob/v0.18.0/docs/rewrite-rules.md).** You write a pattern and its replacement, the compiler proves the rewrite holds, and then it applies it everywhere the pattern shows up.

```mettle
rewrite clamp_twice(x: int64, lo: int64, hi: int64) -> int64 {
    from clamp(clamp(x, lo, hi), lo, hi);
    to clamp(x, lo, hi);
    where lo <= hi;
}
```

To see what all of this produced, `mettle expand` prints the result back as plain Mettle. `comptime` can now build types, strings and tables too, and `comptime for` runs over ranges.

## Proofs and checks

**[Effects](https://github.com/The-Mettle-Project/Mettle/blob/v0.18.0/docs/effects.md).** You declare where an effect comes from and where it isn't allowed to go, and the compiler works out the rest across the call graph. `alloc`, `asm` and `syscall` come built in. Here the audio mixer can't call into rendering, and it can't allocate:

```mettle
effect Render;

fn gl_draw() with Render { ... }

fn mix_audio() forbids Render, alloc { ... }
```

**Declared types.** Write `type Quad = int32 where value % 4 == 0;` and the compiler proves it holds. When a declared range bounds the operands, the overflow check goes away too.

**Deadlines.** With `fn tick() where cycles < 400`, the compiler costs the function's longest path using the target's cost model, and the build stops if it can't prove the claim.

**Run-time checks.** For things that can only be checked while the program runs, there are new flags: `--check-overflow`, `--check-proofs`, `--check-effects`, `--check-tasks` and `--check-deadlines`. `--safe` got sharper as well. It tracks which allocation each pointer came from, so it can tell you when you touched the wrong object. It follows strings built at run time, and it bounds-checks `s[i]`.

## Live programs

Run `mettle live app.mettle` and it builds and starts your program. From then on every save becomes a patch, and the program picks it up at its next `quiesce;`.

Every frame on the stack moves to the new code and keeps its locals by name. If you changed a struct's layout, globals, locals and heap objects get converted, even to and from columns. If the program faults, it waits for the save that fixes it and continues from the last quiesce point. If a patch was a mistake, `--live-undo` takes it back, and `--live-at-tick N` switches every running copy on the same tick when several copies have to agree.

A live build runs 0.7% slower as a geometric mean over Suite 3, though single programs move up to 8% either way from code layout. It works on Windows x64 and Linux x64. [The docs](https://github.com/The-Mettle-Project/Mettle/blob/v0.18.0/docs/live.md), `examples/live` and `examples/settle` are the place to start.

## Threads

Put `@parallel` on a `for` or `while` loop and it runs across all the machine's cores, with one accumulator per thread for reductions. `std/parallel` adds parallel fills and zeroing on top.

`std/schedule` lets you describe a frame as a const: its phases, the effect held in each, the function each runs and which thread runs it. From that, the compiler generates a wrapper per phase and a dispatcher per thread.

Underneath, `malloc` now keeps a per-thread cache of small blocks. Linux worker threads get a guarded stack and their own signal stack, and they start through glibc whenever a program binds a shared library. Crashes on several threads at once can all recover, and `mettle_crash_set_quiet_recovery(1)` lets a hook handle one without printing a report.

## Targets and linking

**[macOS](https://github.com/The-Mettle-Project/Mettle/blob/v0.18.0/docs/macos.md)** is supported. `x86_64-macos` and `aarch64-macos` emit Mach-O, and `--build` links through `cc` against the hosted runtime. CI runs it on Apple silicon, and I've run it on an M4 Pro under macOS 26.6.

On Windows, `--shared` emits a DLL with exports and no entry point. The setup program is written in Mettle now too, with its own window and LZMA decoder. It replaces an older install in place and takes `--silent`, and [its README](https://github.com/The-Mettle-Project/Mettle/blob/v0.18.0/installer/README.md) has the details.

Targets are data you can edit. `mettle target <triple>` prints a built-in target as a Mettle const, and `--target desc.mettle` builds for one you wrote. Feed a printed description back in and you get the built-in target byte for byte. Freestanding x86-64 and AArch64 targets can pick their own argument registers. You can go further and describe a whole machine: `mettle machine` prints the machine a program describes, and `mettle emulate` assembles a program for it and runs it. `examples/machine` has one with eight registers and six instructions.

Two smaller ones. Small structs now pass and return by eightbyte under System V, in public functions, through typed function pointers and to C. And `x86_64` and `aarch64` import guards let a module choose per CPU, which is how `std/socket` and `std/file` get the right Linux system call numbers on each.

## GPU

**Metal** joins CUDA. `--emit-metal` lowers kernels to Metal Shading Language and `std/gpu` launches them, so one Mettle source runs on both, as `examples/gpu_inference` shows.

**Register tiles** give you a value the whole subgroup holds in registers, like `var o: float32[16, 256] layout fragment_c = 0.0;`, and the compiler keeps it inside a register budget it never goes over.

**Numerics contracts** are for kernels that must give the same bits whatever their tile shape, warp split or block shape. Mark them `@numerics(C)` and the build either proves it or fails.

**`mettle tune`** tries the variants of a kernel family on your device and writes the winner to a file you check in. Normal builds read that file and measure nothing.

The type system knows more about the GPU too. Pointers carry address space and alignment (`float32 global align(16)*`), tiles carry shape and element order, and `std/warp` adds `Uniform<T>` and collective effects. `float16` and `bfloat16` are bit exact on every backend. Inside a `@test`, `dispatch` runs the kernel's grid in the interpreter, so you can test kernels with no driver or device.

There's a long tail of smaller additions: `tensor_mma` takes block-scaled int8 and Q4_0 weights as stored, inline PTX takes explicit operands, and there are built-in intrinsics, `dispatch grid_indirect`, `gpu_flush`, `tensor_scale_rows` and `workgroup_uniform`. `std/gpu` links on Linux and can poll a stream or event, and Nsight Systems can profile Mettle programs.

## Language

**[Control flow gives values](https://github.com/The-Mettle-Project/Mettle/blob/v0.18.0/docs/control-flow.md).** `if`, `match`, `switch`, blocks and loops now work anywhere an expression does, and a function's last expression is its return value. `if` conditions can drop their parentheses too.

```mettle
fn round_up(n: int32) -> int32 {
  if n < 16 { 16 } else { n * 2 }
}
```

**Inferred local bindings.** A local `var` or `const` can leave its type off when the line already says what it is.

```mettle
var count = 0;
var total = (int64)0;
var node = new Node;
var rows = load_rows(path);
const LIMIT = 512;
```

A literal, a cast, `new`, a call, a lambda, a place, a comparison, or arithmetic whose operands agree all state a type, so `count` above is `int32`. Mixed-width arithmetic, struct and array literals and `Some(5)` don't count, and the error tells you the type to write when the compiler knows it. Signatures, struct fields and global `var`s still spell their types out, and `mettle expand` shows you the type the compiler picked.

A few smaller things landed too. A local `const` can size an array. `T[,]` and `T[,,]` are ranked slices with an extent per dimension: `v[i]` drops a rank, `new T[m, n]` builds one, and a view can cross a kernel launch. `syscall` is a built-in, functions take up to 128 parameters, and octal literals use `0o`. A generic function can carry lambdas, and `&f<T>` takes the address of an instance. Generic structs take methods, so `b.get()` works on a `Box<int64>`, and a function type can be a type argument, as in `Box<Fn(int64) -> int64>`. A lambda goes anywhere a `Fn` value is expected, including a local, a parameter, a struct field or the result of a call.

## Standard library

The standard library grew from 732 to 1282 exported functions, and most of the growth is in talking to the network and the operating system. [The reference](https://github.com/The-Mettle-Project/Mettle/blob/v0.18.0/docs/standard-library.md) covers all of it.

For networking, `std/socket` does IPv4 and IPv6 with timeouts, poll, epoll and non-blocking accept, `std/dns` looks up names, and `NetStream` gives you one byte stream over sockets and TLS alike. On top of that sit `std/http` with HTTP/1.1 parsers, framing, URLs, writers and a client, `std/websocket`, `std/hpack`, `std/http2` with gRPC message framing, and `std/h2conn`, an HTTP/2 client and server connection with flow control.

For files and processes, `std/file` does positioned reads and writes, sync, truncate, locks and memory maps. `std/fs` handles stat, directories and links, `std/path` handles path text, and `std/process` spawns, waits, kills, captures output and handles signals.

For the system, `std/time` has wall and monotonic clocks, `std/datetime` does UTC dates, ISO 8601 and HTTP dates, and `std/sync` has a mutex, condition variable, reader/writer lock and semaphore that all keep their deadlines. `std/env`, `std/random`, `std/term` with raw mode and window size, `std/dl`, and `std/linux` with named wrappers for common system calls are new as well.

For data there's `std/collections` with `List<T>` and `HashMap<K, V>`, `std/hash`, and `std/encoding` for hex and base64, URL-safe included. The compiler's own interface lives in `std/rule`, `std/meta`, `std/layout`, `std/pass`, `std/regalloc`, `std/target`, `std/machine`, `std/live`, `std/parallel`, `std/schedule`, `std/numerics`, `std/tune` and `std/warp`.

## Packages

Mettle has a package manager now. `mettle pkg` installs from [the registry](https://the-mettle-project.github.io/Mettle/registry/), which is static files on this project's GitHub Pages site, and it works on Windows, Linux and macOS.

```bash
mettle pkg add regex
```

```mettle
import "regex";
```

There are already 40 packages. For the web there's `raize`, a Phoenix-style framework, with its core, API, auth, session, realtime and template packages, plus `fetch`, `grpc` and `flux_orm`. For crypto and compression there's `mtls` (TLS 1.3 and 1.2), `cryptex`, `press`, `erasure`, `sha256` and `hmac`. For media and windows, `window`, `glint` (OpenGL 4.6), `mythic`, `canvas`, `font`, `etch`, `audio`, `mistplot` and `tui`. For systems work, `alph` (Erlang-style actors), `sandbox`, `sysinfo` and `log`. And for data and text, `json`, `csv`, `codec`, `regex`, `args`, `semver` and `uuid`.

Versions work like this: a requirement names the oldest version a project works with, and the resolver takes the highest version anything asks for, so a new release changes nothing until someone asks for it. `mettle.lock` records each package's SHA-256, and `install` checks every archive and unpacked folder against it. `--frozen` fails if the lock doesn't match what the project requires. A package can say where it builds with `platforms = linux windows` in its `mettle.package`.

Publishing is a pull request. CI refuses any change to a version that's already published, then installs the newest version of every package through `mettle pkg`, compiles a program that imports it and runs its `@test` functions. Downloads need `curl` on your `PATH`, and [the docs](https://github.com/The-Mettle-Project/Mettle/blob/v0.18.0/docs/packages.md) have the rest.

## Correctness

Four of the bugs fixed here were in 0.17.0, and they're nasty enough to call out.

The first was a global written through a pointer. `main` passed `&g` to `f(p: int32*)`, and `f` read `g` before and after `p[0] = 7`. A debug build kept the old value in a register across the write, so a program whose answer is 57 printed 55.

The second was `defer` reaching a returned value. With `defer done = 0` after `return done`, the caller got whatever the cleanup left behind, at every optimization level, for scalars, structs, strings, slices and tagged enums alike.

The third was a family. A release build spots common loops, like a popcount, a word count, a byte compare, a dot product or an insertion sort, and swaps in a fast kernel. Several of those swaps ignored work the loop did besides the idiom, or the signedness of the elements, or a step that wraps, and copy propagation missed that an inlined `memcpy` writes the local it copies into. Ten programs added for this release give a wrong answer under 0.17.0 at `--release` and nothing to warn you. Every swap now checks that its kernel accounts for everything the loop does.

The fourth was math. `sin(1e22)` returned 7.76e101 and `sin(1e300)` returned infinity, because argument reduction only held up to about 1e7. `sin`, `cos` and `tan` now reduce any argument exactly. Every function in `std/math` comes within one ulp of the true result, checked against mpmath, and `sqrt` is correctly rounded.

Beyond those, I fixed casts that changed signedness, unrollers that trusted a loop limit a call could move, System V parameter homing, imports, generics in function types and `sizeof`, closures that captured the first binding of a shadowed name, string literals through function pointers, AArch64 float results from indirect calls, a timed mutex wait that lost its deadline, and a Linux program that hung after `main` with a thread still alive. A string local that got reassigned, or a string a call built fresh, used to leak every time. Both are freed now. `floor`, `ceil`, `trunc` and `round` keep the sign of zero, `round_i64` no longer rounds 0.49999999999999994 up, `isqrt` holds at the top of `int64`, and `fract` stays below 1. A `@test` function that `main` calls stays in the build.

The test corpus grew from 943 to 1566 `.mettle` programs. CI runs the MIR verifier after lowering, after every MIR pass and after allocation, and the nightly runs the self-checking generators plus a scaling check that fails when doubling a program more than triples its compile time or memory. The last rounds of bugs came out of pointer and parameter fuzzers, a flag matrix over the whole suite, `--verify` run across the 225,000 lines of Mettle in the registry, and fuzzers for loop idioms, generics, closures and the standard library.

## Diagnostics and tooling

You can see a lot more of what the compiler did. `mettle why` explains a fact that held, in the same words a refusal would use, and `--explain` now lists the types it proved, the effects it inferred, the rules it ran and every extern the build took on trust.

If you want to know what each mechanism cost, `--report-proofs`, `--report-effects`, `--report-rules` and `--report-meta` tell you, and each one has a budget flag. `--record-trace` writes down what a run did, and `mettle check-trace` holds it to your trace rules.

When the compiler does crash, it leaves a bundle in `METTLE_ICE_DIR` with the report, the input, the command line, every `METTLE_` knob, the backend's dump and the IR, which is everything I need to fix it.

Smaller things: M0125 warns when you compare signed with unsigned, and a new warning catches constant signed arithmetic that wraps. Type mismatches print the function's signature, a local whose initializer failed stops reporting undefined at every use, and a call through a bad pointer gets reported at run time. `-V` and `--version` print the version, and `-O0` is accepted.

## Performance

**Generated code.** I measured both releases in one session, every Suite 3 program against its own C twin under clang -O3, best of 15 pinned runs. 0.17.0 ran at 1.18 times clang and 0.18.0 runs at 1.04, with the same answers on all 16. Thirteen programs gained on clang: `bytecode_vm` runs at 0.42, `sudoku_solve` went from 1.33 to 0.74, and `json_parse` from 1.62 to 1.15. Three went the wrong way, with `interp_ast`, `physics_grid` and `diff_lcs` each losing 4 to 5 points.

Underneath, the optimizer builds SSA by default, the allocator colours graphs with Briggs and George coalescing, and the backend relaxes branches to their short forms, places blocks by estimated frequency and threads switch dispatch through its arms. If you want more, `--pgo-gen` and `--pgo-use` profile a run on your own input, and `--assume-no-signed-overflow` is an opt-in promise that signed narrow arithmetic stays in its type.

**Layouts** land within about 1% of hand-written code. Summing one field of 1048576 records 100 times takes 8033 us with hand-written columns and 8030 us with `@soa`. Two passes of `physics_grid` take 23571 us on a plain struct, 23821 us with `@hot_cold` in slices and 23715 us with `@hot_cold` through `T*` fields, all with the same hash. The cost to know about is pointer size: a `T*` field is 24 bytes where a thin pointer is 8, so chasing 65536 shuffled nodes 200 times takes 155241 us against 149727 us.

**LLM inference.** Systm's Potentia runs its GPU kernels in Mettle. Against llama.cpp on one RTX 5060 Ti with Gemma 4 12B and 26B-A4B, it gets to the first token 1.7 to 2.4 times faster, generates a reply 1.07 to 1.41 times faster, uses 8.5 to 23.5 times less RAM on the 26B model and spends 19 to 38 percent less energy per token.

**Runtime.** The Linux runtime reads the clock through the vDSO now, and `--safe` struct calls dropped from 2800 ns to 400 ns.

### Compile speed

All that optimizer work has a price: an ordinary build takes longer than it did in 0.17.0. The pathological cases went the other way, and anything that hit a quadratic before is much faster. These are the same inputs through both compilers, each built with GCC at -O2, best of three:

- 89,612-line generated program at `--release`: 2.2 s to 3.5 s
- The same program at debug: 1.5 s to 2.0 s
- `json_parse` at `--release`: 0.05 s to 0.10 s
- 4000 array reads at `--safe`: 7.6 s to 1.0 s
- 5000 live locals at `--release`: 0.58 s to 0.38 s
- 20000 live locals at debug: 29.5 s to 3.0 s

Even so, the 89,612-line program builds 3.4 times faster than the same program through clang -O3, 3.5 s against 11.7 s.
