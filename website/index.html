This is your language.

Mettle is a systems language.
All of this works today.

Language

  • Structs, methods and tagged enums

    match requires a case for every variant, or a default.

  • Generics and closures

    fn add_one<T: Addable>(v: T) -> T compiles to one copy per set of type arguments. Fn(int32) -> int32 captures by value, and fn(int32) -> int32 is a bare pointer.

  • Slices and shaped views

    T[] carries its length and T[,] its extents. T[32, 32] puts the shape in the type, and every index into it is proven.

  • defer and errdefer

    defer runs on every path out of a scope. errdefer runs only when the function returns an error.

  • Interpolated strings

    Any expression fits in the braces: "twice={n * 2}".

  • A standard library

    Files, sockets, HTTP, threads, processes, collections, hashing, encoding, arenas and allocators.

Compile time

  • Generate declarations from your types

    comptime for walks typeof(T).fields, a table's rows or a range, and emits functions and constants.

    struct Packet { id: int32; len: int16; flags: uint8; }

comptime for f in typeof(Packet).fields {
  const ident("OFFSET_", f.name): int64 = f.offset;
}

println("OFFSET_len = {OFFSET_len}");
println("OFFSET_flags = {OFFSET_flags}");OFFSET_len = 4
OFFSET_flags = 6

  • Read what was generated

    mettle expand prints the whole program after expansion, as normal Mettle.

  • Test and trace without building

    mettle test runs @test functions in the compiler's interpreter, with no codegen and no link. mettle trace prints the source with the values each line took.

       1 | fn total(n: int32) -> int32 {
   2 |   var sum: int32 = 0;                                <- sum = 0
   3 |   for i in 0..n {                                    <- i = 0, 1, 2, 3, ..., 4 (5x)
   4 |     sum = sum + i;                                   <- sum = 0, 1, 3, 6 (4x)
   5 |   }
   6 |   return sum;
returns 6

  • Embed a file

    import_str reads a file into a string at compile time.

Memory

  • No lifetime annotations

    Ownership is inferred across calls. The compiler reports use after free, double free, leaks, dangling pointers and invalidated borrows at the line that does the damage.

    var data: uint8* = malloc(n);
free(data);
println("checksum = {checksum(data, n)}");warning[M0101]: Use of `data` after it was freed (freed at line 17); this is use-after-free

  • Safe hand-offs to tasks

    Handing a task a pointer into the frame that spawned it, or writing through a pointer already handed to a task, is a compile error.

  • Checked access on request

    --safe checks every memory access not proven in bounds, and stays on under --release.

  • Manual memory

    malloc, new T[n], arenas and std/alloc. There is no garbage collector.

Contracts

  • Types with predicates

    A conversion into a declared type is proven from guards, ranges and arithmetic, or the build stops.

    type Percent = int32 where value >= 0 && value <= 100;

var a: Percent = 40;
var b: Percent = argc * 2;error[P0001]: cannot prove `value >= 0` for `argc * 2`, which 'Percent' requires (its range here is -4294967296..4294967294)

  • Effects through the call graph

    Declare with, forbids, requires and provides where they matter. The compiler infers everything in between and proves it on every build.

    fn log_line() { var p: int32* = malloc(64); free(p); }
fn gain() { log_line(); }
fn mix_audio() forbids alloc { gain(); }error[F0001]: 'mix_audio' forbids 'alloc' but reaches it: mix_audio -> gain -> log_line

  • Races on globals

    Say where code runs with effects, and a global two threads write with nothing ordering them stops the build.

  • Deadlines

    where cycles < N bounds a function's longest path on the target's cost model. Too slow or unbounded, and the build stops.

    error[D0001]: 'tick' declares a deadline of 20 cycles, and its longest path costs 847 on this target

  • Optimization contracts

    @simd! requires a vectorized loop, @inline! an inlined call, @noalloc an allocation-free call graph and @pure no writes. The build stops at the site that broke it.

    error: @simd! loop was not vectorized: the loop body branches on data (an `if` or `&&`/`||` per iteration); only straight-line loop bodies vectorize

  • Reference twins

    reference names a slower function. Every build runs both on generated inputs and stops when they disagree.

    error[T0001]: `abs_fast` and its reference `abs_slow` disagree: return value was -2147483648, is now 0; (input set 7) abs_fast(2147483648)

  • Checks in the running program

    --check-proofs, --check-effects, --check-deadlines, --check-overflow and --check-tasks trap when a claim fails at run time.

The compiler

  • Ask what it decided

    --explain reports every optimization decision, the reason for each refusal, and what the build took on trust. mettle why prints the chain behind an effect or a proven type.

    checksum (loop @ line 6): vectorized -> vpsadbw, 32-wide byte sum (AVX2)
main (loop @ line 15): NOT vectorized  [store-only-fill]
beliefs: 10 things this build took on trust

  • Write your own rules

    @rule reads the checked program, what codegen made of it, or a recorded run. It can stop the build, or propose a fix that --fix applies.

  for f in p.functions {

      return verdict_fail(f.site, "this module forbids recursion");

  • Teach the optimizer

    rewrite adds an identity from your own code. Both sides run on generated inputs first, and a rule that fails is refused with the input that broke it.

    error: rewrite `drop_clamp` changes meaning: its `from` and `to` sides disagree
counterexample (input set 6) drop_clamp(-1)
divergence: return value was 0, is now -1

  • Validate every pass

    --verify runs each changed function before and after every pass on generated inputs, and reports a divergence with a counterexample.

  • Profile-guided optimization

    --pgo interprets main at compile time, with no training run. --pgo-gen and --pgo-use measure a real run.

  • Read the assembly

    --annotate-asm prints the emitted assembly with the decision behind each instruction, a cost model and a register map.

  • A learned optimizer

    Experimental. --ml-opt runs a graph neural network over the IR after the classical passes. Each rewrite is re-executed and dropped if it diverges.

  • Budgets for build time

    --rule-budget, --proof-budget and --effect-budget fail the build when those passes spend too much.

  • Diagnostics with evidence

    A diagnostic has a code, a caret and the evidence. mettle explain expands any code, and --error-format=json feeds your tools.

Machines

  • Native code

    x86-64 on Windows, Linux and macOS. ARM64 on Linux and macOS.

  • Vectorized loops

    The optimizer vectorizes loops to AVX2, and --simd-report says what each @simd loop became.

  • Loops across cores

    @parallel runs a loop on every core, gives integer accumulators one copy per thread, and refuses a loop it cannot split.

  • GPU kernels

    A kernel is a Mettle function. It compiles to PTX, SPIR-V or Metal, and one dispatch launches it. mettle test runs a dispatched grid in the compiler's interpreter, with no GPU.

    kernel(block = 256) vadd(a: float32*, b: float32*,
                         c: float32*, n: int32) {
  var i: int32 = block.x * block_dim.x + thread.x;
  if (i < n) {
    c[i] = a[i] + b[i];
  }
}

dispatch vadd[work: n](da, db, dc, n);

  • Tensor cores and tiles

    tensor_mma and register tiles are kernel operations, and inline PTX is there for anything else.

  • Frame schedules

    A const table of phases, effects and threads. The compiler checks it and generates the dispatchers.

  • Inline assembly

    asm blocks are assembled by the compiler itself, with Mettle variables as operands.

  • Bare metal and system calls

    @naked, @interrupt, volatile, a chosen link address, flat images and 16-bit real mode. syscall asks the kernel directly, with no stub to link.

  • Edit a target

    mettle target prints a target as a Mettle value. Change its argument registers or cost model and build with --target.

  • Invent a machine

    Describe an instruction set in a Mettle file. The compiler checks it, assembles your program for it, and runs it with mettle emulate.

Running programs

  • Change a running program

    mettle live turns every save into a patch: function bodies, signatures and struct layouts. Frames move to the new code, heap objects convert in place, --live-undo takes it back, and --live-at-tick lands a patch on the same frame in every running copy. Windows and Linux x64.

  • Recover from a crash

    A fault waits for the save that fixes it, then the program continues from its last quiesce. In this recording the fix landed in 256 ms.

  • Crash reports and debugging

    A linked executable names the exception, the function and the stack by default, and -s gets the exact statement. -g writes DWARF, and --debug-hooks instruments a build for the interactive debugger.

  • Profilers

    --profile-runtime times functions, --profile-runtime-ops counts op classes and --profile-blocks counts basic blocks.

  • Record a run

    --record-trace writes down calls, allocations, frees and locks, and mettle check-trace holds the recording to your rules.

Toolchain

  • One toolchain

    Frontend, optimizer, interpreter, code generators, assembler, linkers and runtime in one codebase, with no LLVM and no external assembler. Windows and Linux builds link with its own PE and ELF linkers.

  • Close to C

    16 whole programs average 1.09× the run time of clang -O3, from 0.71× to 1.29×, with the same answers. Against clang -O3 -march=native the average is 1.13× and clang leads on all 16.

    clang 22.1.6 on Windows, on an i7-12700K, best of 15 pinned runs. Under -march=native, clang's physics_grid returns a different checksum. All 16 programs. Run them with tools/benchmark/mc.ps1 -Suite 3.

  • Fast builds

    A generated 90,000-line file builds in 7.6 s. clang takes 16.0 s.

  • Its own runtime

    No C runtime, garbage collector or scheduler on Windows and Linux. The safety, profiler and debug parts link only when you ask for them.

  • Call C, and be called

    extern and export, with structs by value in both directions under the Windows x64 and System V rules. Bind a .so, or emit a .so or a DLL.

  • Your own frontend

    Drive libmtlc's C API and your language gets the IR, the optimizers, code generation and the linkers.
