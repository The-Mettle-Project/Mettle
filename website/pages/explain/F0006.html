F0006Two threads write the same global and nothing orders them

Reported by the compiler as an error or warning.

mettle explain F0006

Two functions write one global, and the effects each needs place them somewhere different: one runs where an effect it requires is provided, the other where a different one is, and no effect appears in both requirement sets. Nothing in the program says which write lands last.

Example

effect Sim;
effect Render;
var frame: int32 = 0;
fn tick() requires Sim { frame = frame + 1; }   // F0006
fn draw() requires Render { frame = 0; }

An effect BOTH writers require is what says they are ordered, because whoever provides it runs them one at a time. That is what a lock is, spelled as a requirement:

effect FrameLock;
fn tick() requires Sim, FrameLock { frame = frame + 1; }
fn draw() requires Render, FrameLock { frame = 0; }

Fixes

  • give both writers a requirement they share, and provide it around each write with the lock the program already holds

  • give each thread its own copy and combine them at a point one thread owns

  • move one of the writes to where the other one runs

Nothing is said about a global whose writers need no placed effect at all. A program that declares no provides is not making a claim about where its code runs, and this check makes none about it.
