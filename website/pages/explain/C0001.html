C0001Two kernels of a numerics contract compute an output differently

Reported by the compiler as an error or warning.

mettle explain C0001

Every kernel marked @numerics(C) promises the same bits for each output element as every other member of C, given the same inputs. The build proves it: each harness of C runs in the compile-time interpreter with every input byte a symbol, so each output element comes out as its computation, the ordered chain of rounding operations and where every operand came from. Two members that agree compute the same chain.

These two do not. The message names the element, the claim (numerics_same) that compared it, and the first operation where the chains part, with its line in each kernel. For an MMA step it names the A or B element that differs; a sum of the same terms added in another order is named as that sum. A different rounding order, an extra operation (x + 0 * v is not a no-op: v can be infinite, and the sum can lose a negative zero) or a different operand all part the chains.

Fix: make the kernels compute the same thing, or take the kernel out of the contract.
