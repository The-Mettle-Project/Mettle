G0001A kernel holds more tile registers at once than its budget

Reported by the compiler as an error or warning.

mettle explain G0001

A register tile is a subgroup's value held in registers, each work item its share, and tiles never spill. The backend states what each tile costs a work item (PTX: an f32 fragment_c M x N tile costs M*N/32 registers, an f16 fragment_a M x K tile M*K/64, a row vector M/8), takes the tiles live at each point of the kernel, and compares the peak with the work item's register limit: 255, or the multiple of 8 below 65536 / block threads when that is smaller. This kernel went over. The message names the line of the peak and every tile live there with its cost.

A run of element-wise tile operations is computed one element at a time, so a tile made inside such a run and used only there costs nothing. --explain and --report-gpu-types print every tile, its cost, its live lines and the peak.

Fix: shrink a tile, end one's life earlier, or keep an operand in memory and let tensor_mma read it there.
