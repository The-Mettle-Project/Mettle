# Architecture

How a Mettle source file becomes a running program, subsystem by subsystem.

The repository holds two halves. The frontend turns Mettle source into IR.
libmtlc, the backend, turns IR into machine code and links it. They meet at the
IR and at the public C API in [`include/mtlc/`](../include/mtlc/), which is
what lets [another frontend](embedding.md) drive the same backend.

## The pipeline

```text
source
  |  lexer            src/lexer
  v
tokens
  |  parser           src/parser
  v
AST
  |  semantic         src/semantic     types, borrows, memory, comptime
  v
checked AST
  |  monomorphize     src/semantic     one copy per set of type arguments
  v
  |  IR lowering      src/ir
  v
IR  <----------------------------------- another frontend enters here
  |  optimizer        src/ir/optimizer
  v
optimized IR
  |  code generation  src/codegen      x86-64 / ARM64 / PTX / SPIR-V
  v
object
  |  linker           src/linker       internal PE, or ld / gcc / link.exe
  v
executable
```

Everything runs in one process. There is no external assembler, no assembly
text anywhere in the pipeline, and no LLVM.

## Frontend

### Lexer

`src/lexer` produces tokens. Keywords resolve through two length-bucketed,
sorted tables: language keywords matched exactly, and inline-assembly
mnemonics and register names matched without regard to case. A binary search
within one length bucket settles a lookup in a few comparisons, which matters
because most identifiers are not keywords and used to pay for the whole chain.
The tables are generated by `tools/gen_lexer_keywords.py`.

Identifiers are interned, so later phases compare pointers.

### Parser

`src/parser` is recursive descent producing an AST. Two things beyond the
grammar earn their keep.

Error recovery resyncs at block boundaries, so one missing brace reports once
rather than cascading. The parser tracks the previous token and the enclosing
group so a message can say what it was in the middle of.

A speculative parse handles `<`: after an identifier it may open a generic
call's type arguments or be a comparison. The parser tries the first, and
backtracks. A diagnostic from an abandoned speculation must not survive the
backtrack, which was a real bug once.

### Semantic analysis

`src/semantic` is the largest frontend piece, split by concern:

| File | Concern |
|------|---------|
| `type_checker*.c` | Types, declarations, statements, expressions, matches |
| `type_checker_memory.c` | Use after free, double free, leaks, out of bounds |
| `type_checker_safety.c` | `--safe` check placement and static elision |
| `type_layout.c` | Sizes, alignment, field offsets |
| `symbol_table.c` | Scopes and name resolution |
| `import_resolver.c` | The import graph, path resolution, visibility |
| `comptime_expand.c` | `comptime for`, at both statement and module scope |
| `monomorphize.c` | One copy per set of generic type arguments |
| `register_allocator.c` | Frontend-side allocation hints |

Nothing is inferred about a binding's type, which removes a whole layer this
stage would otherwise carry. What is inferred is analysis: the borrow and
memory checks derive their facts and report only what they prove. There is no
ownership syntax to write.

Module-scope `comptime for` sits between two type sweeps: the written types are
registered before it runs, and the declarations it generates are registered
after. That ordering is why a generated type cannot be reflected on from inside
the iteration that generated it.

### IR lowering

`src/ir/ir_lower*.c` walks the checked AST and builds IR, one file per concern:
expressions, statements, addresses, types, `defer`, and the `switch` and
`match` desugars.

Lowering has no local scopes of its own, so it reads types from the checked AST
rather than looking names up again.

## The IR

A function is a list of instructions with labels and branches. Values are
named. Types are attached to instructions, so code generation never re-derives
one.

[The IR model](libmtlc/ir.md) documents the instruction set and the
control-flow rules. [The type system](libmtlc/types.md) documents `MtlcType`.

## Optimizer

`src/ir/optimizer` holds around forty passes. The driver in
`ir_optimize_pass_driver.c` runs them; `ir_optimize_pipeline.c` decides the
order.

The shape is: canonical form to a checked fixpoint, then a recognizer
worklist, then a tail of lowering cleanups.

### Canonical form

Loop canonical form runs first, because every recognizer behind it reads loop
bodies and assumes that form. It runs twice; a third sweep was measured to
change nothing.

The core simplifications run to a fixpoint: copy and constant propagation,
common subexpression elimination, branch simplification, reassociation, dead
write elimination, jump threading, and the block and label cleanups.

A convergence check fails the build when the fixpoint does not settle, so a
pass pair that undoes each other's work is caught rather than spun on.

### Recognizers

A recognizer matches a loop shape and replaces it with a kernel. They are
listed once each in dependency order and driven by a worklist, so a claim by
one re-queues the loops another might now match.

The vectorizers are the largest family: integer and float reductions, maps,
dot products, byte kernels, quantized integer kernels, fills, scans and
searches, extrema, predicated counts, and some serial recurrences. Each emits
AVX2.

An exact-shape recognizer is bait for rot: the code it matched drifts, the
recognizer silently stops firing, and nothing notices. `IrMustMatch` guards
pin the shapes that must keep matching, and the build fails when one stops.

### Interprocedural work

Inlining sits between two loop-canonicalization stages, because inlining a body
into a loop changes what the recognizers can see. Loop-invariant call hoisting
runs once before inlining and once after.

Tail-recursion elimination runs before any inlining, since converting the tail
first is cheaper than inlining it and then converting.

Whole-program alias facts are built once the call graph has settled. They index
functions by pointer, so nothing may consult them after the graph changes
again.

### Contracts

`@simd!`, `@inline!`, and `@noalloc` are checked after every optimization that
could satisfy them has run. A violated contract fails the build and names the
site that defeated it.

### Passes worth naming

`sroa` splits struct locals into register-promotable scalars. `layout_factor`
re-maps provably private allocations into a compact layout.
`null_check_licm` hoists a null check out of a loop. `prefetch_indirect`
inserts prefetches ahead of an indirect access. `egraph_simplify` is an
e-class pilot, inert unless `METTLE_EGRAPH=1`.

`METTLE_SKIP_PASS` turns any of them off by name, which is how a miscompile is
bisected. `METTLE_TIME_IR_PASSES` times them.

## Code generation

`src/codegen` has four targets and one shared object writer.

### x86-64

Two backends, and most functions take the first.

MIR, in `src/codegen/binary/mir*.c`, is a machine-level IR with real register
allocation. `mir_lower.c` lowers IR to MIR, `mir_regalloc.c` allocates,
`peephole.c` cleans up, and `mir_encode.c` emits bytes.

Allocation is Chaitin-Briggs graph coloring by default;
`METTLE_LINEAR_ALLOC` selects a linear allocator instead. The pool is the full
general set plus xmm0-15, with R10 and R11 held back as scratch.

Loop rotation converts a top-testing loop to a bottom-testing one under three
guards, the third being that the latch must be the only edge into the header.

When MIR cannot take a function it falls back to a spill-everything backend
that keeps every value on the stack. `--explain` reports which functions fell
back and why, because the difference is large and silent otherwise.

### ARM64

`src/codegen/binary/arm64_*.c`: its own encoder, ABI, MIR bridge, and
disassembler. It emits a self-contained AArch64 Linux executable or a
relocatable object. Bringing it up keeps surfacing x86 bugs, because parity
tests exercise shapes the x86 path had been getting away with.

### PTX and SPIR-V

`ptx_emitter.c` and `spirv_emitter.c` consume the same IR. Device code is
reachability-based: a plain function called by a kernel becomes a device
helper, and unrelated host functions are omitted.

A shared IR call-graph verifier rejects recursion, indirect calls, external
calls, and host launches from device code, so the rule is identical for every
frontend and both GPU backends.

`gpu_detect.c` asks the CUDA driver what the local card is, falling back to
`nvidia-smi` when the driver library is out of reach.

### Object writers

`binary_emitter.c` writes COFF and `elf_emitter.c` writes ELF, from one set of
relocation kinds. `startup.c` writes the target's startup object.

## Linker

`src/linker` is a complete PE linker: `coff_reader.c`, `elf_reader.c`,
`symbol_resolve.c`, `relocation.c`, `import_lib.c`, and `pe_emitter.c`.

Its distinctive rule is that runtime objects' symbols are overridable
defaults, so a program defining `strlen` replaces the runtime's without a
duplicate-symbol error, while the runtime keeps calling its own.

Link-time section collection drops what nothing reaches.
[Linker and build pipelines](linker-build-pipelines.md) has the full matrix.

## Runtime

`src/runtime/freestanding.c` owns the startup path and the basic services. It
includes no standard C header and links no libc.
[Runtime model](runtime-model.md) covers what it provides and how excision is
gated.

`src/runtime/swap.mettle` is the first runtime component written in Mettle,
compiled by the compiler this build produces.

## The interpreter

`src/ir/ir_interp.c` executes IR with a real memory model: strings with their
bytes, structs, arrays, globals, heap allocation, and closures.

Four features run on it, which is why its coverage matters:

| Feature | Uses it to |
|---------|-----------|
| `mettle test` | Run `@test` functions with no codegen |
| `mettle trace` | Print a function's values line by line |
| `--pgo` | Interpret `main()` and count calls |
| `--verify` | Execute each function before and after every pass |

`ir_verify.c` is the validation harness: snapshot, run both, compare,
quarantine a diverging pass for that function, and continue from validated IR.

`ml_gnn.c` and `ml_opt.c` are the learned optimizer, gated by the same
harness.

## Diagnostics and reports

`src/error` owns the reporter: severities, codes, snippets, labels, notes, the
JSON form, and `mettle explain`.

`ir_optimize_explain.c` produces the `--explain` report. It re-runs the
optimization stages against a hypothesis to test a suggested fix before
printing it, which is why the report says what happened rather than what might.

`mir_annotate.c` produces `--annotate-asm`: per-instruction provenance, a cost
model, recovered loops, and register lifetimes.

## Debugging

`ir_debug_hooks.c` instruments for the interactive debugger. The runtime side
speaks over a named pipe and a DAP adapter drives it, so source-level
debugging needs no gdb, no PDB, and no DWARF consumer.
