Mettle / Diagnostics
How to read the output

Anatomy of a diagnostic

Every error and warning the compiler prints has the same five parts. Once you can name them, the rest of this site is a lookup.

── tests/diag_call_notes.mettle:6:20 ──────────────────────────────
error[E0003]: Function 'add' expects 2 arguments, got 3

  ────┬─────────────────────────────────────────────────────────────
    5 │  fn main() -> int64 {
    6 │      var r: int64 = add(1, 2, 3);
      ·                     ^^^ expected 2 arguments, got 3
    7 │      return r;
  ────┼─────────────────────────────────────────────────────────────
      │  note  function 'add' defined here
    1 │  fn add(a: int64, b: int64) -> int64 {
      ·     ^^^
  ────┴─────────────────────────────────────────────────────────────

  help: pass 2 arguments, or change 'add' to take 3

The five parts

The rulefile:line:column

The top rule carries the location, and nothing else. It is file:line:column so a terminal or an editor can turn it into a jump. Every diagnostic opens with one, which is also what separates one diagnostic from the next when several are printed.

The headlineseverity, code, message

error[E0003]: Function 'add' expects 2 arguments, got 3. The severity is error, warning, or note. The bracketed code is stable across compiler versions, which is what makes it worth grepping for and what this site is indexed by.

This line is never wrapped, even on a narrow terminal, so a pattern that matches a whole message keeps matching one line.

The framesource and gutter

The quoted source sits in a table: line numbers in a gutter, a bar, then the line itself. The line the diagnostic is about is shown with one line of context either side. Tabs are expanded to four columns so the caret lands under the character you see rather than the byte offset.

The caretspan and label

^^^ marks the exact span, not just the line, and the text after it is the short version of what is wrong there. The headline says what happened; the label says which part of the line caused it. They are deliberately different sentences.

Notes and helpthe second location, the fix

A note points at a second place that matters: the declaration a call disagrees with, the previous declaration a duplicate collides with, or the comptime iteration a generated declaration came from. Notes share the parent's frame, behind a crossing rule, so one error reads as one object.

help: is the suggested fix. Where a fix is offered it has been checked, not guessed.

Several errors at once

The compiler does not stop at the first error. It reports every one it can reach and then summarizes:

──────────────────────────────────────────────────────────────────
  error: could not compile `bad.mettle` due to 2 previous errors
  help: for more about this error, run `mettle explain M0118`

The parser resynchronizes at block boundaries, so one missing brace reports once instead of cascading into a page of nonsense. Diagnostics that are only consequences of an earlier one are suppressed rather than printed.

Severity

error fails the build. warning does not. Most of the memory diagnostics are warnings, because the code they describe is legal and wrong. The ones that cannot possibly be intended, such as returning the address of a local, are errors.

The codes

E0001–E0007 are the compiler's categories: lexical, syntax, semantic, type, scope, I/O, internal. M0101–M0119 come from the memory, borrow and range analyses, which stamp a finer code over the category they would otherwise carry.

Any of them can be expanded in the terminal:

mettle explain E0003
mettle explain list        # the whole index

Or read the same text here: every code the compiler can print. Both come from the same table in the compiler, so they cannot disagree.

Machine-readable output

--error-format=json writes one JSON object per diagnostic to stderr, newline-delimited, so a reader can consume them as they arrive:

mettle --error-format=json bad.mettle -o bad.obj
{"severity":"error","code":"M0118","message":"Integer 300 is out of range for 'int8'",
 "file":"bad.mettle","line":2,"column":17,"length":3,
 "label":"does not fit in 'int8' (-128..127)",
 "help":"'int8' holds -128..127. Widen the type, or cast to say the wrap is meant: (int8)value",
 "notes":[]}

length is how many columns the caret spans; notes carries the secondary locations, each with its own message.

Controlling the presentation

Colour and box-drawing are decided per run, from the terminal:

  • NO_COLOR turns colour off; CLICOLOR_FORCE turns it on even when stderr is not a terminal; CLICOLOR=0 and TERM=dumb also turn it off.
  • METTLE_DIAG_COLUMNS pins the width when the terminal misreports its size.
  • METTLE_DIAG_UNICODE=0 forces the ASCII frame (-, |, +) if your console cannot render box characters.

Redirected output gets no colour, no box characters, and no line wrapping. That is deliberate: where a message breaks should never depend on the width of someone's terminal, so a captured build log is stable.
